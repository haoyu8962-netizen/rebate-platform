- 平台自动审计在依据里有出处的：iOS UITests 对 7 个关键页调用 `performAccessibilityAudit()`（DSX-62）；Android Compose / Robolectric 测试启用 ATF 无障碍检查（DSX-71）；鸿蒙设备用例对关键页断言可点控件 `accessibilityText` 非空、命中区 ≥48vp（DSX-84）。三者都是「先只报告、生成基线」的 CI 守卫，**可作为本清单的辅助证据，不能代替读屏录屏**（05 QA-12 验收列要「读屏录屏或自动检测报告」；静态 / 自动检查验证不了读屏实际行为，03 §10.5）。

## 4. 专项（05 QA-12「检查」各项）

> 原生端不涉及的两项：「表格表头与单元格的关系」（页面组里没有原生表格，AC-S1-158 也没有该步；归 QA-12-web / AC-S1-157 ②）；「Esc 关闭」（原生端改为读屏返回手势或【关闭】，AC-S1-158 ④）。

### 4.1 控件名称（列表 / 行操作读「动作 + 该行主标识」）

依据：05 QA-12「控件名称（表格行操作读出『动作 + 该行主标识』）」；变更记录 §1-4（「如『审核 提现单 W123』，不只读『审核』」）；AC-S1-158 ⑥。

| 步骤 | 做法 | 通过 |
| --- | --- | --- |
| 4.1-a | 每页逐个聚焦只有图标的按钮：返回、关闭、清除输入、显示 / 隐藏金额（AC-S1-158 ⑥ 列举） | 读出名称（如「返回」「关闭」），不读「按钮」或文件名 |
| 4.1-b | 在 `OrderList` 聚焦每行的行内操作（如复制按钮） | 读出「动作 + 该行主标识」，同屏多行同名操作可区分 |
| 4.1-c | 列表行整体：`OrderList`、`Search` 结果卡、`Home` 商品卡 | 行读成一句，平台图标不重复播报、筛选项读出选中（app-order-list.md §6） |
| 4.1-d | 「显示 / 隐藏金额」切换后再聚焦 | 读屏名称随状态变（AC-S1-105 期望 ①：`amount_mask.hide` → `amount_mask.show`，可选功能，UI 稿采用后才计）；金额隐藏时读屏名称也不泄露金额（app-wallet.md、app-order-list.md §6） |
| 4.1-e | 每页逐一核对 §5.1 列出的该页「读屏名称」约定 | 与规格一致 |

### 4.2 模态与焦点（弹窗、底部抽屉、半屏）

依据：05 QA-12「对话框与抽屉的模态与焦点（打开时进入、焦点圈在其中、Esc 关闭、关闭后回到触发控件、叠层时只暴露最上层）」；AC-S1-158 ④。

| 步骤 | 做法 | 通过 |
| --- | --- | --- |
| 4.2-a | 每页打开一个弹窗或底部抽屉（如钱包页说明弹层、详情页弹层，见 AC-S1-185 ② 所举） | 焦点进入弹窗标题，读作弹窗 / 对话框 |
| 4.2-b | 打开状态下持续右滑越过最后一个控件 | 焦点不跑到背后页面；背后页面读不到 |
| 4.2-c | 用读屏返回手势（iOS 双指 Z 形擦除、Android / 鸿蒙读屏返回手势——鸿蒙手势「待原生线确认」）关闭；再打开一次用【关闭】关闭 | 两种方式都能关；关闭后焦点回到触发它的按钮 |
| 4.2-d | 叠层：在弹层里再触发二次确认（如 `Withdraw` 提交时的二次验证，规格提到 `A11yFocusStepUp`） | 只有最上层可读、可聚焦 |
